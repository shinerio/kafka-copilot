# agents.md — Kafka Pilot skill 维护纪律

本文件规定 `SKILL.md`（kp CLI 使用指南）的维护边界与更新纪律。任何修改 `SKILL.md` 的人（人或 Agent）都须遵守。

## 1. SKILL.md 的内容边界（强制）

`SKILL.md` **只描述 kp 的 CLI 用法**，不得包含以下内容：

- ❌ **REST API / HTTP 端点**：不写任何 `/api/*`、REST 调用方式、请求体字段、本地 HTTP 服务的接口说明等。
- ❌ **常见故障排查 / troubleshooting 章节**：不单列“故障排查”章节或表格。命令的“坑”只在对应命令的注意/风险段落里顺带点出，不单独成章。
- ❌ **与 CLI 无关的其他内容**：如 Web UI 操作说明、界面按钮、产品宣传、安装/编译等前置动作。
  - 仅当某条内容**直接服务于“怎么用 CLI 命令”**时才保留。
  - 例：`kp serve` / `kp desktop` / `kp stop` / `kp restart` 作为 CLI 命令本身可以出现（它们是命令行调用），
    但**不得展开描述其 Web UI 用法**（如“用界面填”“访问 Web UI”等）。
  - 安装、编译、构建等前置动作一律不写——skill 只覆盖“使用能力”。

> 理由：skill 的定位是“指导 Agent 如何使用 CLI”。REST、故障排查、Web UI 等偏离这个定位，
> 会造成 Agent 误用入口或引入无关上下文，降低指令的精确度。

## 2. 必须随代码同步更新的内容

当 kp 源码发生变化时，以下 `SKILL.md` 内容必须同步更新（准确性优先于“看起来全面”）：

- 命令清单（顶层命令、子命令）
- flag 名称 / 默认值 / 含义
- 退出码及其含义
- `scan` / `produce` 等命令的**输出字段口径**（字段名、何时出现、含义）
- `produce` 脚本沙箱的 `ctx` 变量与约束

## 3. 验证方式

- 改完 `SKILL.md` 后，用 `kp schema` 核对该列出的命令与退出码是否一致。
- 对 `scan` / `produce` 的输出字段，对照 `internal/scan`、`internal/produce` 源码确认字段名与出现条件。
- 提交前用全文检索确认无 `REST` / `/api` / `Web UI` / `故障排查` 等越界字样残留。

## 4. 禁止事项

- 不要把安装 / 编译等前置动作写进 `SKILL.md`（skill 只覆盖“使用能力”）。
- 不要为了“看起来全面”而加入 REST / 故障排查 / Web UI 等越界内容。
- 删除或新增命令后，必须同步更新 `kp schema` 的对照与全文交叉引用。
